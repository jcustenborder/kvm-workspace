# Local Session API Implementation Plan

> **For agentic workers:** Use executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Add an authenticated, documented localhost REST API for named KVM sessions.

**Architecture:** Node HTTP in Electron main routes through existing device/window
state. Browser-only session actions operate firmware controls, with no native
capabilities exposed to device pages. Keep validation and HTTP testable outside Electron.

**Tech Stack:** Electron, CommonJS, Node HTTP/crypto/fs, node:test, Playwright.

## Global Constraints

- Loopback `127.0.0.1:53241`; bearer token on all endpoints.
- Unique DNS-label device names; legacy records load for manual correction.
- No new dependencies; retain internal device IDs and existing security boundaries.
- Match the approved spec in `../specs/2026-11-09-local-api-design.md`.
